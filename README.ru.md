## Зачем нужен RAS

Большинство средств автоматизации отчётов останавливается на тексте. RAS рассматривает отчёт как спроектированный и проверяемый артефакт: выбирает форму коммуникации, сохраняет цепочку доказательств, разрешает визуальную систему, создаёт DOCX и PDF из одной модели, при необходимости добавляет редактируемый PPTX и проверяет результаты перед выдачей.

Опишите нужный результат обычным языком:

> «Сравни варианты для совета директоров и порекомендуй путь.»

> «Создай обзор KPI с понятным графиком тренда.»

> «Преврати это исследование в синтез с опорой на источники.»

> «Объясни инцидент, первопричину, влияние и корректирующие действия.»

RAS превращает запрос в структурированный проект с независимыми Markdown-блоками, реестром источников, визуальным контрактом и квитанцией качества.

## Установка в Codex или Claude Code

RAS — навык для создания отчётов, упакованный в виде плагина для Codex и Claude Code. Установите его в используемый вами агент. Команда `ras-report` — отдельный необязательный рендерер для прямого или скриптового запуска.

### Codex

В терминале Codex добавьте marketplace стабильного релиза `v0.1.0` и установите плагин:

```bash
codex plugin marketplace add CharlesArea/ras --ref v0.1.0
codex plugin add ras@ras-marketplace
```

Чтобы установить плагин через браузер приложения Codex, выполните только первую команду для регистрации marketplace. Затем откройте `/plugins`, выберите **RAS — Report Anything Skill** и нажмите **Install plugin**. После этого начните новый чат Codex и вызовите `$ras`.

```text
Use $ras to turn these notes into an evidence-grounded decision memo and
deliver DOCX, PDF, and an editable PPTX companion.
```

### Claude Code

Добавьте marketplace RAS и установите плагин из терминала Claude Code:

```bash
claude plugin marketplace add CharlesArea/ras
claude plugin install ras@ras-marketplace
```

В интерактивном сеансе можно выполнить `/plugin marketplace add CharlesArea/ras`, затем `/plugin install ras@ras-marketplace` и выбрать область установки. Навык вызывается командой `/ras:ras`; настройку рендерера запускайте через `/ras:setup`. Подробности — в [руководстве Claude Code по установке плагинов](https://code.claude.com/docs/en/plugins/install).

### Файлы плагина и marketplace

Переносимый манифест находится в [`plugin.json`](plugin.json). Каталоги marketplace есть для [Codex](.agents/plugins/marketplace.json) и [Claude Code](.claude-plugin/marketplace.json); также доступны манифесты, совместимые с [Codex](.codex-plugin/plugin.json) и [Claude Code](.claude-plugin/plugin.json).

## Быстрый старт

Попросите установленный навык создать нужный отчёт. Укажите, если вам нужны подробный анализ, внешнее исследование или файлы DOCX и PDF.

В Codex:

```text
$ras Создай подробный, основанный на доказательствах отчёт о сравнении
экономики до и после COVID. Изучи актуальные первичные источники, объясни
изменения и ограничения, подготовь DOCX и PDF.
```

В Claude Code:

```text
/ras:ras Создай подробный, основанный на доказательствах отчёт о сравнении
экономики до и после COVID. Изучи актуальные первичные источники, объясни
изменения и ограничения, подготовь DOCX и PDF.
```

RAS определяет быстрый, стандартный или глубокий план по запросу. Для создания DOCX/PDF нужен локальный рендерер и Python 3.11 или новее; подтвердите его настройку, когда агент предложит её. PPTX — дополнительный формат, для которого нужен поддерживаемый хост с Node.js и Artifact Tool.

## Необязательно: запускать рендерер напрямую из CLI

Этот раздел нужен только для прямого или скриптового запуска рендерера. Он не устанавливает навык:

```bash
python -m pip install "ras-report-anything[render] @ git+https://github.com/CharlesArea/ras.git@v0.1.0"
```

Требуется Python 3.11 или новее.

Инициализируйте проект отчёта:

```bash
ras-report init reports/my-report \
  --request "Create an evidence-grounded decision memo from these notes" \
  --archetype decision-memo
```

Глубина определяется по обычному языку; глубину, режим исследования и число страниц можно переопределить:

```bash
ras-report init reports/economy-deep-dive \
  --request "Create a detailed comparison of the economy before and after COVID" \
  --depth deep --research web --pages 15
```

Доступны профили `quick`, `standard` и `deep`. Разрешённый план можно посмотреть так:

```bash
ras-report plan reports/economy-deep-dive/manifest.yaml
```

Отредактируйте `manifest.yaml`, `sources.yaml` и Markdown-блоки, затем выполните проверку, сборку и QA:

```bash
ras-report validate reports/my-report/manifest.yaml
ras-report build reports/my-report/manifest.yaml --formats docx,pdf,pptx
ras-report qa reports/my-report/manifest.yaml
```

DOCX и PDF — основные форматы. PPTX — опциональный редактируемый компаньон, для которого нужен поддерживаемый хост с Node.js и Artifact Tool.

### Выходные форматы

| Формат | Поддержка | Среда |
| --- | --- | --- |
| DOCX | Основной формат | Python и `python-docx` |
| PDF | Основной формат | Python и ReportLab |
| PPTX | Опциональный редактируемый компаньон | Поддерживаемый хост с Node.js и Artifact Tool |

### Структура проекта отчёта

```text
reports/my-report/
├── manifest.yaml       # запрос, стиль, блоки, выходы и квитанция QA
├── sources.yaml        # происхождение и поддержка утверждений
├── blocks/*.md         # независимые возобновляемые единицы содержания
├── assets/             # предоставленные или созданные визуальные материалы
├── build/              # каноническая модель и промежуточные визуалы
├── qa/                 # квитанции и изображения отрендеренных страниц
└── dist/               # финальные DOCX, PDF и опциональный PPTX
```

## Что создаёт RAS

RAS подходит для отчётов, которым нужны структура, суждение и прослеживаемость:

| Назначение | Подходит для |
| --- | --- |
| Бриф для руководства | Управленческие сводки и короткие обзоры |
| Записка для решения | Варианты, компромиссы, рекомендации и следующие шаги |
| Синтез исследования | Выводы на основе нескольких источников |
| Глубокий анализ | Тренды, причины, последствия и интерпретация |
| Сравнительная оценка | Сравнение до/после, вариантов, поставщиков или политик |
| Предложение и roadmap | Бизнес-кейсы, стратегии, планы и этапы |
| KPI и статус | Метрики, графики, прогресс и операционный ритм |
| Аудит, риск и соответствие | Контроли, пробелы доказательств, выводы и меры |
| Технический отчёт | Архитектура, системы, инциденты и расследования |
| SOP и кейс | Повторяемые процедуры и документированные примеры |

Маршрутизатор предоставляет шестнадцать архетипов; если форма уже задана в запросе, явные настройки имеют приоритет.

### Повторно используемые шаблоны

Шаблоны — это редактируемые и возобновляемые наборы блоков, а не заблокированные макеты:

| Семейство | Включённые формы |
| --- | --- |
| Решения и сравнения | Записка для решения, сравнительная оценка, предложение/бизнес-кейс |
| Исследования и анализ | Синтез, глубокий анализ, расследование/первопричина |
| Операционный ритм | Статус/прогресс, KPI, стратегический roadmap |
| Риск и assurance | Аудит, соответствие/риск, postmortem |
| Техника и процедуры | Техническая архитектура, политика/SOP, кейс |

Точную схему блоков можно посмотреть командой `ras-report template inspect <template>`.

### Лёгкое планирование содержания

Каждый новый пакет автоматически сохраняет план с диапазоном страниц, диапазоном слов, целью по слайдам и бюджетом слов для каждого раздела. «Подробный анализ» выбирает deep, а «краткий бриф» — quick. Это помогает расширять контекст, доказательства, последствия и ограничения без необоснованного заполнения.

## Как это работает

1. **Маршрутизация запроса:** определяются архетип, аудитория, тон, уровень доказательности, геометрия страницы, визуальный стиль, плотность и акцент.
2. **Планирование содержания:** определяются глубина, целевые страницы, бюджеты и режим исследования. Внешнее исследование требует `web` или ясного запроса.
3. **Независимые блоки:** каждый блок имеет стабильный ID, цель, статус, источники, бюджет макета и необязательный визуальный контракт.
4. **Единая дизайн-система:** до рендеринга задаются тема, брендовые токены, компоненты, типографика, палитра графиков, язык диаграмм, отступы и ритм страниц.
5. **Рендеринг и проверка:** DOCX и PDF создаются из одной модели; PPTX сохраняет нативные графики, редактируемые таблицы и источники в заметках. QA проверяет структуру, соответствие разделов, доступность, читаемость и целостность страниц.

## Дизайн-система

Темы меняют не только цвета, но и иерархию, обложку, смысловые панели, таблицы, графики, диаграммы, типографику, отступы и композицию.

| Тема | Характер | Лучше всего для |
| --- | --- | --- |
| `minimal` | Спокойная и компактная | Короткие отчёты без украшений |
| `editorial` | Тёплая и повествовательная | Брифы руководства и сюжетная работа |
| `data-forward` | Чёткая, ориентированная на метрики | KPI, сравнения и дашборды |
| `institutional` | Формальная и структурированная | Политики, аудит и соответствие |
| `technical` | Точная, как чертёж | Архитектура и эксплуатация |
| `narrative` | Выразительная и ритмичная | Кейсы и длинные синтезы |

Файл `.ras/brand.yaml` может переопределить цвета, шрифты, отступы, токены компонентов, палитры графиков и токены диаграмм. Markdown-проформатирование **жирным**, *курсивом* и `code` поддерживается единообразно.

## Модель доказательств

Материалы пользователя — основная доказательная база. Внешнее исследование используется только по запросу или при явном разрешении. Реестр источников хранит происхождение, а блоки ссылаются на него стабильными маркерами вроде `[S1]`.

```yaml
sources:
  - id: S1
    title: Official source title
    publisher: Publisher
    url: https://example.com/source
    publication_date: "2026-01-01"
```

Проверка контролирует ссылки на источники, поддержку утверждений, подписи и альтернативный текст, безопасные пути и неразрешённые placeholders.

## Визуалы и доступность

Графики принимают спецификации `bar`, `line` и `pie` с метками, значениями, подписями и альтернативным текстом. Диаграммы используют небольшую семантическую грамматику и создают оригинальные SVG- и PNG-ресурсы. Информативные визуалы получают видимую подпись, альтернативный текст, метаданные изображений в DOCX и детерминированный ресурс в модели сборки.

## Разработка

```bash
python -m unittest discover -s tests -v
```

Полный приёмочный прогон:

```bash
python -m unittest discover -s tests -v
ras-report validate examples/executive-brief/manifest.yaml
ras-report build examples/executive-brief/manifest.yaml --formats docx,pdf,pptx
ras-report qa examples/executive-brief/manifest.yaml
```

Необязательные зависимости для рендеринга объявлены в [`pyproject.toml`](pyproject.toml):

```bash
python -m pip install -e ".[render]"
```

## Область проекта

RAS v1 сфокусирован на отчётах DOCX и PDF с опорой на доказательства, опциональных редактируемых PPTX-компаньонах, многоразовых шаблонах и лёгком планировании содержания. Веб-отчёты, приложения-таблицы и совместное редактирование пока находятся вне текущего контракта рендерера.
